# VDR QA v0.14.0 — исправление анализа k6

Это накопительное обновление для существующих v0.10–v0.13.
Распакуйте fixes-overlay в корень проекта с заменой файлов. .env и отчёты
reports/performance/ архивом не затрагиваются. Затем повторите команду:

~~~bash
make perf-analyze REPORT=reports/performance/load-2026-10-16T04-48-28-514Z.json
~~~

Новый нагрузочный прогон не нужен: анализатор читает уже сохранённый JSON.
Полный архив подходит для установки в пустую папку.

Причина: k6 --summary-export сохраняет показатели метрик непосредственно в
metrics.<name> и успешные пороги как false (не нарушен). Анализатор ожидал
формат handleSummary с values и {ok:true}, из-за чего выдавал null и ложный FAIL.
Теперь оба формата поддерживаются; отсутствие необходимых метрик приводит к
ошибке, а не к вымышленному PASS. p99 остаётся null, если он не сохранён k6.

Проверено на Node 22.16.0: 71/71 unit/regression/guard checks, QA TypeScript,
CLI на образце экспортированного JSON (вердикт PASS), отрицательный сценарий
порогового провала. Реальный личный JSON пользователя недоступен в этой среде;
исходный прогон k6 по предоставленному выводу прошёл все пороги.
