# VDR QA v0.5 — next local execution

This is a standalone QA *overlay*, not the actual VDR frontend/backend repo. The uploaded Work branch has not been supplied; the Cypress Component Testing and NestJS/Postgres suites cannot be correctly wired/tested against the real application until it is available. No such coverage is claimed here.

## What changed
- Auth LHCI path is **relative** to the QA process working directory (`lighthouse/login.cjs`), fixing duplicated prefix errors.
- LHCI skips brittle `page.waitForNetworkIdle` during auth (user-proven fix).
- Auth-mode `chromeFlags` warning removed; Puppeteer launch still receives explicit sandbox flags.
- Optional test-object audits via `LHCI_ROOM_ID`, `LHCI_FOLDER_ID`, `LHCI_FILE_ID` (must be real UUIDs owned/accessible to the test account).
- Shared exact route list validates collection: every target must have **exactly** `LHCI_RUNS` collected reports and no runtime errors.
- Offline `lighthouse:analyze` outputs per-route medians from any verified `qa-summary.json`.
- Latest observed, user-provided Lighthouse results included in `docs/lighthouse-observed-results.md`.

## Local setup
1. From `vdr-qa-starter/`, run `PUPPETEER_SKIP_DOWNLOAD=1 npm install`. Existing `node_modules` can be reused; do not paste credentials into terminal output.
2. Use existing `.env` with `OWNER_EMAIL` and `OWNER_PASSWORD`. For remote demo set `LHCI_WEB_BASE_URL=https://virtual-data-room-ten.vercel.app`, `LHCI_ALLOW_REMOTE=1`.
3. Configure `CHROME_PATH` to a working Chromium executable. On systems where Chromium sandbox is unavailable, explicit **opt-in** `LHCI_CHROME_NO_SANDBOX=1` is supported. Restrict this to disposable QA environments and trusted targets.
4. To find IDs: sign in, open a test Data Room / folder / PDF and copy only the UUID from the route (`/room/<uuid>`, `/folder/<uuid>`, `/file/<uuid>`). Do **not** use `/share/<token>`; do not include querystrings.
5. In your shell:

```bash
export LHCI_ROOM_ID='00000000-0000-0000-0000-000000000001'   # REPLACE with real UUID
export LHCI_FOLDER_ID='00000000-0000-0000-0000-000000000002' # optional
export LHCI_FILE_ID='00000000-0000-0000-0000-000000000003'   # optional
LHCI_RUNS=1 npm run lighthouse:check
LHCI_RUNS=1 npm run lighthouse:auth
npm run lighthouse:analyze
```

**Important:** zero UUIDs above are placeholders, not actual valid VDR IDs; replace or unset. If auth preflight reports missing resource, unset the invalid ID and retry.

For a stable baseline, run `LHCI_RUNS=3 npm run lighthouse:auth`. Lighthouse will audit Dashboard, Shared With Me, and each configured test object. Results: `reports/lighthouse/auth/qa-summary.json`; raw `lhr-*.json` under `.lighthouseci/`, plus private HTML/JSON in `reports/lighthouse/auth/`.

Read offline baseline:

```bash
npm run lighthouse:analyze -- evidence/lighthouse-auth-user-run-2026-10-16.json
```

Run regression tests for tooling:

```bash
npm run test:framework
npm run lighthouse:check
```

## Safety / limitations
Only run remotely against approved demo/test accounts. Do not mutate production data. LHCI artifacts may contain names, URLs, file identifiers and contents: share only redacted reports. Lighthouse LCP is a lab navigation metric and not a substitute for Core Web Vitals RUM or actual permission tests. HTML snapshots / responses can contain secrets.

Component tests (Cypress) and DB integration tests (Jest + Prisma/PostgreSQL) require a copy of the **current Work branch** and reproducible isolated infra; adding placeholder tests as passing tests would be misleading.

## Playwright read-only document smoke (optional)

The new `tests/ui/document-pages.spec.ts` tests work with existing test objects and perform **no data mutations**. Set the same `LHCI_ROOM_ID`, `LHCI_FOLDER_ID` and `LHCI_FILE_ID` and the owner credentials, plus `CHROMIUM_EXECUTABLE_PATH` to the extracted browser. Then run:

```bash
npm run test:ui -- tests/ui/document-pages.spec.ts
```

Skipped tests are NOT passes. If the object is still loading or a test fails, attach trace and screenshot under `test-results` / HTML report.
